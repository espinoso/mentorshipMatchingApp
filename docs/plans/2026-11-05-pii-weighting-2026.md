# 2026 Matching: in-app de-anonymization, weighted scoring, 2026 schema

**Status:** proposed (for review before coding)
**Context:** IMFAHE International Mentor Program 1:1 matcher. This year's Google Form exports
now carry PII (name/email, +LinkedIn for mentors); last year's "CODED" files did not. Maria &
Zafira (Nov 3–4 2026, "Matching AI" thread) sent this year's forms + registered mentors, and
last year's data + the human-reviewed final matching for validation. Zafira asked to (a) show/
control the matching "baremos" in the sidebar like the peer-mentoring app, and (b) also avoid
Portugal↔Portugal, not just Spain↔Spain.

## Key architecture facts (verified)
- Scoring is **Jev** (TypeSafe System One), holistic, in `jev_scoring.py`. No editable rubric in
  the UI (removed when Jev was adopted); the "rubric" is `_CRITERIA` + `_INSTRUCTIONS` in code.
- Normalization (`Normalization/merge_*_skills_enhanced.py`) feeds the Haiku LLM **only**
  field/specialization/skills/level text (`row[pre_cols[...]]`) — **never name/email/LinkedIn** —
  and the normalized output schema has no PII. So PII never reaches Jev or Claude today; it is
  simply dropped. This feature **captures** it into session RAM instead of dropping it, and
  re-attaches it locally for display.
- Pipeline: upload → `process_file_with_progress` (normalize) → `mentees_df`/`mentors_df` (standard
  schema, IDs) → `generate_matrix_jev` → `apply_country_restrictions` (soft penalty) →
  `hungarian_assignment` → matches → on-demand Claude reasoning.

## Privacy contract (must hold)
- name / email / LinkedIn live **only** in `st.session_state` (RAM), keyed by assigned ID.
- Never written to disk, cloud, logs, or debug output; never sent to Jev or Claude.
- De-anonymization happens only at the display layer and in the locally-downloaded Excel.
- Uploaded raw bytes already live only in session memory; the identity map is never serialized.

## Workstream 1 — Capture identity map + 2026 schema ingestion (PR 1)
**Files:** `Normalization/merge_mentee_skills_enhanced.py`, `merge_mentor_skills_enhanced.py`,
`Normalization/shared_utils.py` (or a small new `anonymize.py`), `normalization_utils.py`,
`ui_upload.py`, `info.py` (column maps), tests.

- Detect PII columns by header (`Full name`, `Email`, mentor `…LinkedIn…`). Mentee form has no
  LinkedIn.
- During normalization, after the ID is assigned, pop PII into an identity map
  `{str(ID): {"name": ..., "email": ..., "linkedin": ...}}` and return it alongside the df
  (`process_*_file` → `(df, report, identity)`), threaded up through
  `process_file_with_progress` → `run_file_processing` → `st.session_state["identity_<entity>"]`.
- Extend `pre_cols` / column detection so the **2026** mentor (25-col) and mentee (20-col) exports
  normalize cleanly, including the new fields carried into the standard schema:
  availability/time-zone, preferred meeting frequency, mentoring/communication style (and mentor
  years-abroad). Keep the existing CODED-file path working (no PII present → empty identity map).
- De-anonymize at the edges only: the Review/Results match cards and `_matches_report_bytes`
  Excel show name (+email/LinkedIn) looked up from the map; sanitize still applies to exports.
- **Tests:** identity round-trips by ID; a CODED file yields an empty map; the AI-facing df has no
  PII columns; the map is not referenced by any serialize/debug path.

## Workstream 2 — Weighted multi-dimension scoring + baremos sidebar + Portugal (PR 2)
**Files:** `jev_scoring.py`, `app.py` (`render_sidebar`, `generate_matrix_jev`), `info.py`
(weights + country defaults), `ui_processing.py` (sidebar baremos panel), tests.

- **Step 0 (verify before building the full run):** confirm Jev `system_one` returns **multiple**
  scored questions in one call (`questions={dim: Score(...)}` → `resp.scores[dim].score`). Measure
  per-call cost on a ~20-pair slice and report it before any full-cohort run (non-profit cost).
  Fallback if multi-question is unsupported/expensive: compute level & availability deterministically,
  reserve Jev for field/skills/goals.
- Replace the single holistic score with **six dimension scores** (each a Jev Score question with
  its own criteria), rescaled 0–100, combined as a **weighted average** with the sidebar weights
  (normalized to sum 1). Dimensions & default weights:
  | dimension | default |
  |---|--:|
  | field_specialization | 30 |
  | goals_mentoring | 20 |
  | skills | 20 |
  | level_seniority | 15 |
  | availability | 10 |
  | style | 5 |
- `apply_country_restrictions` soft penalty runs **after** the blend (unchanged); extend the
  default country list to `["spain", "portugal"]` and add a Portugal toggle.
- **Baremos sidebar:** weight sliders (live, normalized, with the defaults above), the cap, and
  Spain/Portugal toggles. Jev is holistic per-dimension, so the sliders blend dimension scores —
  they are real weights, not cosmetic.
- **Tests:** weighted blend math (weights → expected score); normalization of weights; per-dimension
  parsing from a faked multi-question Jev client; Portugal penalty wired like Spain.

## Workstream 3 — Validation against the human final (PR 3)
**Files:** `benchmark/`-style script (or `tests/`-adjacent), not shipped in the app path.

- Parse `FINAL ALL MATCHING- REVIEWED JUNE 2026.xlsx` (hand-formatted; title row then pairs) into
  mentee→mentor pairs.
- Run the full pipeline on last year's CODED 2025 data with default weights; compare to the final:
  overlap %, exact-pair rate, and a breakdown of divergences.
- **Framing:** plausibility check, not reproduction. The final was human-reviewed (manual
  overrides), ~40 ULL students appear only in the final (late arrivals), and last year used the old
  scorer. "Reasonably close" = healthy; "wildly off" = a bug.
